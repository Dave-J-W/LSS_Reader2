# Tools: every demonstration and figure generator

Generated by `python -m lss_toolbox --render` from `lss_toolbox/catalog.py`;
do not edit by hand (`tests/test_toolbox.py` fails when this page and the
catalogue differ). The same catalogue builds the reader's **Tools** menu and
the Tools window (`python -m lss_toolbox`, or Tools > All tools… in the
reader), so this page, the menu and the scripts cannot drift apart.

How it stays current (owner, 2026-11-23: "built from what's in the repo and
so don't drift"):

- every run executes the repository's script as it is now, into a folder of
  its own (`~/.lss_reader/tools/<item>/<date-time>`, or
  `$LSS_READER_TOOLS_DIR`), with a `run.json` naming the command and the git
  commit; nothing is written into the repository unless asked (Tools window:
  "Replace the committed products", only with the settings that made them,
  usually the defaults);
- the options a page offers are read from the script's own argparse parser
  each time (`lss_toolbox.introspect`), never copied;
- `python -m lss_toolbox --audit` reruns every item with the settings that
  made its committed products and compares: images pixel for pixel, tables
  and text apart from how they were run (the command line they echo, their
  timings, the lines an item names as `volatile`), and a figure that prints
  its git revision apart from that stamp (found by a second run with a dummy
  revision, `LSS_TOOLS_REVISION`); a text item's printed output against its
  committed file, and a check item by its exit code. This is the measured
  staleness; the last
  audit is `docs/reports/tools_audit.md`. With `--record` it keeps, for each item
  whose products matched, the fingerprints of the modules the run actually
  imported, the files it read and the products it reproduced, in
  `lss_toolbox/verified.json`;
- an item's committed products are **current** while that record holds:
  nothing the rerun used has changed since. A fingerprint of Python code
  ignores docstrings and comments (`lss_toolbox.fingerprint`). Without a
  record, or after the products changed, they are flagged **possibly
  stale** when the script, a repository file it imports, or a named input
  changed its code after the products' last commit (`lss_toolbox.staleness`;
  `python -m lss_toolbox --stale` lists them all);
- the tests check that every script in `tests/tools/` is an item (or a
  listed helper), that every option a variation sets exists in its script,
  and that every figure committed under `docs/` belongs to an item.

A **variation** is a change of settings the documents describe ("change
this parameter and regenerate the figure to see that"), with the document
line it comes from. In the Tools window, choosing one fills the form; Run
makes the figure. Here each is written as the command line it runs.
`{out}` is the run's folder. Times were measured in the development
container on 2026-11-23 with the defaults shown.

## The Tools window

Opened from the reader (Tools > All tools…, or any item) or on its own (`python -m lss_toolbox [--item ID]`). Left: the items by menu; right: the chosen item's page (made when first shown). Labels and tooltips, from `lss_toolbox/texts.py`:

| Control | Label | Tooltip |
|---|---|---|
| `tree` | Items | Every demonstration and figure generator of the repository, by menu. The same list is the reader's Tools menu and docs/TOOLS.md (lss_toolbox/catalog.py). |
| `variationCombo` | Settings | Defaults, or a variation the documents describe ("change this parameter and regenerate to see that"). Choosing one fills the form; the tooltip of each says what it shows and where the documents say so. |
| `sourceButton` | Source | Open the document the chosen variation comes from (its passage is the text after # in the variation's tooltip). |
| `form` | Options | The script's own options, read from its argparse parser each time the page opens (never copied, so they cannot go out of date). An empty field uses the script's default (shown greyed). {out} stands for this run's folder. |
| `freeEdit` | Arguments | Arguments typed as on the command line (scripts without options). |
| `specButton` | Open file | Put the SPEC file open in the reader into the SPEC field. |
| `commandEdit` | Command | The exact command the run executes from the repository root: copy it to rerun the same thing in a terminal. |
| `runButton` | Run | Run the script as it is in the repository now, in its own process, into a new folder (~/.lss_reader/tools/<item>/<date-time>, or $LSS_READER_TOOLS_DIR). The reader stays usable while it runs. |
| `stopButton` | Stop | Stop the running script. |
| `repoCheck` | Replace the committed products | Write into the repository folders that hold this item's committed products instead of a run folder. Only with the settings that made them (the defaults, or the variation "As committed") and public data. Commit them with the change that made them stale (AGENTS.md rule 11). |
| `statusLabel` | — | Whether the committed products are older than the code that makes them. First from the verified record (lss_toolbox/verified.json, written by python -m lss_toolbox --audit --record): a rerun matched the committed products, and nothing it imported or read has changed since. Otherwise from git history: the script, the repository files it imports and its named inputs. Changes to comments and docstrings do not count. "May be stale" is a hint; Run with the defaults and compare with the committed products to know. |
| `docsBox` | Docs | The documents that explain this item; each button opens one. |
| `log` | Output | What the script prints, as it runs. |
| `runCombo` | Show | Which products to show: a run of this item (newest first) or the committed products in the repository. |
| `compareCombo` | Compare with | Show a second set beside the first: the committed products or an earlier run. Images with the same name are compared pixel by pixel. |
| `diffCheck` | Differences | Show where the two images differ (white) instead of the second image. |
| `compareAllButton` | Compare all | Compare every image of the shown set with its counterpart and list which are the same, which differ (by how many pixels) and which are new. |
| `fileList` | Files | The images and text files of the shown set; = same as the compared set, ≠ different, + not in the compared set. |
| `openFolderButton` | Folder | Open the shown folder in the file manager. |
| `openSpecButton` | Open in the reader | Open the SPEC file this run wrote in the reader. |
