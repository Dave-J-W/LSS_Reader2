# Breadcrumbs for the manual writer

The user manual is not in scope yet (owner, 2026-11-19), but whoever writes
it later needs to find, for every user-visible feature, what it does, where
it is, what its default is, why, and how a script does the same. This file
is the index; it points at the places that hold the details, and it grows
with each feature commit (AGENTS.md rule 11).

## Features by area of the window

Each line: feature — where — default — script — notes entry (date).
"Notes" means `physics_notes.md`.

### Opening data
- Open a SPEC file; non-SPEC files and repeated scan numbers handled
  quietly — File menu — Notes 2026-11-17 (Stage 1).
- Messages pane (no blocking dialogs); durable log and per-SPEC log —
  bottom of the window — `reader_log.py`; Notes 2026-11-17 "Stage 0 built".
- Preferences (calibrated foils; known ratio auto-use and threshold) —
  File > Preferences — `lss_core/preferences.py`; Notes 2026-11-18
  "Calibrated foils in the reader".

- A data line with a different number of values from the rest of its scan
  (in a file SPEC is still writing, the line being written) is left out,
  with one message in the Messages pane (2026-11-23); the scan's other
  lines are read as usual. Before, such a scan read as empty.

### Fluorescence detector
- File > Preferences > Fluorescence detector: elements 1–7 of the
  multi-element detector summed into one spectrum per point (default all,
  EXAFS; "Centre" selects element 1, the central one, for XFNTR); the MCA list shows "ch …"; `channels=`
  in scripts. Dead time: corrected by the 7-element detector itself; the
  1-element one by real/live time (D48).

### Time
- SPEC plot x axis `Time_s` (selected scans on one true timeline) and
  `Time_from_start_s` (each scan from its own start); how the times were
  obtained is in the item's tooltip (`lss_core/timing.py`, D46, D50).

### Saving to the workbook (F66, D53)
- "Save" beside every Export (SpecPlot, Reflectivity, Cuts, MCA integral) and
  "Save to workbook" in the GID menu: one click stores what is shown in
  `<SPEC file>_reader.xlsx` in the output folder (sheets Scans, Saved, Data,
  Fits, Trends, Maps, Settings; kind, scans, version, note, settings per result; every
  sheet filtered and sortable). Every Save asks for an optional note
  (owner, 2026-11-21); Shift-click saves without asking; Preferences > Saving
  turns the question off (then Shift-click asks). Export still writes the legacy text files and is unchanged.
  `lss_core.workbook`; Notes 2026-11-21.

### Fitting (F22)
- SpecPlot: the scan is fitted as a peak, an edge (half-cut: edge width = beam
  FWHM) or a plateau, whichever fits best; the title says which (P9 fixed).
  A scan that its background alone fits (a flat noisy line, a ramp such as
  Epoch; χ² p > 0.05) is not fitted: the title shows the highest point
  only, no fit line (owner, 2026-11-23; `peaks.is_flat`). A sample-height
  scan (sh, plotted against sh) is fitted only when its signal is at least
  twice its background and only with a FWHM over 20 µm (owner: "we always
  get good signal"; `peaks.height_scan_options`).
- MCA tab: "Fit lines" and "Fit options..." (lines of all selected spectra,
  the sum fixing position and width; intensities like Sum All). With
  several lines placed, the intensity is the first line given (the
  element's), not the tallest (2026-11-24, F90 P5).
- Fit options are kept between sessions (preferences) and in the workbook.

### Monitor and absorbers (affect every tab)
- Absorber factor field, "from E", "cal" — main panel — `absfac=` in
  scripts — OUTPUT_DECISIONS "Absorber factor per unit".
- Image list "Abs=n" / "Abs=?" (unknown setting) — Notes 2026-11-19
  "unreadable `#A`".
- "/ gain" and "/ photon" beside the monitor choice (MCA, SpecPlot; reach
  cuts, background, GID) — off — `monitor_gain=True`, `per_photon=True`
  — Notes 2026-11-17 and 2026-11-19.
- Errors pane: Legacy / Budget, monitor model — `errors=` — Notes
  2026-11-17 "The error budget, built".

### Burn tests
- A burn test is analysed as a GID burn when Det_Th > 2°, otherwise as a
  reflectivity burn (owner, 2026-11-23; F87).

### SpecPlot
- Log x or log y with nothing positive to show on that axis (all values
  <= 0, or infinite after dividing by a zero monitor) leaves the axis
  linear, with a note in the status bar (2026-11-23).
- Plot any column against any other, normalised (by Monc when the scan has
  it, since 2026-11-23; the column before the last otherwise); "Point #" labels (on) —
  Notes F55; export writes `<name>_<scan>_<x>_<y>[_<monitor>].txt`.

### Reflectivity (Ref Patch)
- Identical scans (repeats of a macro): "Merge" sums each point's counts
  and monitors and divides once, ΣN/ΣM (F81, 2026-11-23; tooltip), so a
  repeat with more monitor counts weighs more; with equal monitors it is
  the old average, which stays as a preference (`repeats_legacy_average`).
  Scripts: `exp.reflectivity(..., merge=[[2, 3]])`, `repeats='mean'` for
  the old average.
- Patch window: fitted factor per join, known-ratio box and line,
  automatic choice — `exp.reflectivity(factors=...)` — Notes 2026-11-18
  "Calibrated foils in the reader"; P29 (Monc at narrow slits).
- Outputs `_ref.txt`, `_rrf.txt` (columns: see `lss_core/reflectivity.py`
  `finish` and the xmodfit contract in `docs/handoff/`).
- "+ covariance" box beside Export/Save (2026-11-22, off by default):
  Export also writes `<name>_ref.cov.json` / `_rrf.cov.json` for XModFit
  (σ_meas, W, Σ). The text files are unchanged. Why a fit needs it, how
  to use it, and what the numbers show:
  `docs/reports/downstream_covariance.md`. Nothing is written if the
  patch on show cannot be replayed (message). Terms to define: counting-only
  error, region weights, scan-scale covariance, pull.

### Fluorescence (MCA tab)
- Window sum ("Sum All"), calibration, normalisation, absorber per MCA
  scan from the last `#A` — `exp.fluorescence` — Notes 2026-11-17
  "Absorber setting of the MCA scans". Output `_flu.txt` [frame, Qz,
  energy, intensity, error].

- Merge (MCA tab): default window 0.1 × the Qz grid step, Qz jitter in the
  error bars; tooltip on the window field; `flu.merge` in scripts. The user
  chooses which scans to merge (one run, wavelength, sample, signal shape).

### Pilatus images, cuts
- "Fit peaks" and "Fit options..." beside the cut plot (D52): every plotted cut
  fitted at once (peaks found by significance over a running-median background,
  Gaussian / Lorentzian / pseudo-Voigt with a polynomial background, weighted by
  the error bars); fits drawn dashed, results in the Messages pane and the
  options dialog, "Save results..." writes a table; `cut.fit(peaks.FitOptions(...))`
  in scripts; `lss_core/peaks.py`. A fit that does not describe the data says so.
- Line/Area cuts: directions Q H, Q V, Pix H, Pix V; axes Pixels / Angles
  / Q; "Sum"; pinhole box (on: S4–detector distance at Det_Th > 1°) —
  `exp.cut` — Notes 2026-11-18 "Pinhole is the default". Q cuts with empty
  default ranges are a known gap (F59, docket). A user complained (2026-11-18)
  that cuts in Qz/Qxy and I vs β are not documented: I vs β works today as
  "Pix V" with axes "Angles"; write this part of the manual first.
  Since 2026-11-23 each frame of a reflectivity scan has its own incidence
  angle (from its Qz; the scan header's In_Rot is the position before the
  scan moved, P47), so the reflected beam sits at β = α on that axis.
- Background images and background-subtracted frames (not scriptable yet).
- The frames display is sticky (F88, owner Q9, 2026-11-24): zoom, colour
  map, aspect, Axes, log (per kind of frame) and typed limits (per kind)
  stay through redraws, frame and scan changes and the next session, and are
  reset only when another SPEC file is opened. Toolbar buttons: **Home**
  (the last zoom box drawn), **Fit all** (the whole frame; also the house
  icon), **Auto scale** (forget typed limits). Defaults (owner Q8,
  Q-IMG-4, 8, 14): log for reflectivity, GID and GISAXS frames, linear for
  direct beam and dark; the top of the scale at the 99.9th percentile of
  the whole selection per Monc with the direct beam masked; viridis;
  nearest pixels; at most 6 tiles, sampled first-to-last, "6 of 9 shown".
  Terms to define: kind of frame, direct-beam mask. `lss_core/display.py`.
- The frame movie (F69, owner Q7, 2026-11-24): 3 or more selected frames
  play as one large frame (the view box: Movie, or Tiles: 4 / 6); the Movie
  button plays any 2 or more. Movie bar: view, ◀, ▶/❚❚, ▶|, a slider (the
  image list marks the frame shown), the counter, speed (2 fps default),
  Loop (off: stops on the last frame), and the frame's scan, point, Qz or
  2θ, time, absorber and Monc. Keys with the image focused: space plays or
  pauses; Left, Up, Back step back and Right, Down, Forward step forward,
  pausing first. Zoom, colour map and the one shared colour scale (per Monc,
  absorber-corrected) never change while it plays. The movie no longer sets
  Axes to Q or ticks Pinhole.
- Everything shown is per Monc (2026-11-23, owner: "all data is default
  normalized by monc, even gisaxs"): the image and its colour range, the
  cuts, GISAXS. "Sum All" sums the frames' counts and monitors and divides
  once, ΣN/ΣM (F91; tooltip): frames with more monitor count weigh more,
  which is the most likely common rate. The old average (and GISAXS in raw
  counts) are preferences, `sum_all_legacy_average` and `gisaxs_raw_counts`,
  for the Reduction options page (F86). Scripts: `exp.cut(..., summed=True,
  sum_mode='mean')` for the old average. Terms to define: effective monitor
  (Monc over absorber factor and gain).
- 2D_Plot tab (x y z text files, e.g. exported maps): Add File, select it, then CMap, Log Int, Min/Max, interpolation. It works again since 2026-11-23 (adding a file had raised an error with matplotlib 3.9 or later). The colour map once listed as 'spectral' is listed as 'nipy_spectral', the same map under the name matplotlib has used since version 2.0; the hidden Apex tab's list, which colours the Reflectivity ROI image, changed the same way.

### GID
- GID worksheet (GID menu > Worksheet): every patch parameter, Patch,
  Defaults, Fit (pinhole distance, diagnostic only), join table — Notes
  2026-11-18 "Pinhole-geometry GID built", 2026-11-19 "Joining Qz levels".
- Worksheet: response "fit" (per column), "beam" (along the beam axis, for a narrow beam;
  shows the beam's centre and FWHM on the sample) or "none"; the 2θ resolution
  (S4 + pixel) is shown with the levels.
- Worksheet: "Footprint window" exact (default: columns that see the lit
  strip through the whole S4 opening) or IDL (centred on the direct-beam
  column, as PD_PIN_RANGE) — `GIDParams(footprint=...)` — P39, D51.
- Worksheet: "Update the map on every change" (on): every check box and drop-down
  re-patches after a short pause, to see each method's effect; the levels line
  shows "frames agree: chi2/dof" per level, the yardstick for comparing
  methods (addendum 3c). Response "physical+fit" (physical scale × a per-column
  refinement).
- Worksheet: response "physical" (the column response from the geometry and a
  Gaussian beam; "Beam (physical)": vertical FWHM µm (0 = fit), centre mm ("fit"
  ticked = fitted), horizontal FWHM mm) and "Apply join factors" (off: the data
  as collected, factors only reported) — `GIDParams(response='physical',
  beam_fwhm_um=…, beam_centre_mm=…, beam_h_fwhm_mm=…, apply_joins=False)` —
  addendum `docs/manual/gid_patching.md` 3b; Notes 2026-11-20.
- Worksheet "Fit" (S4-detector): calibrates the distance from single frames
  (the strongest peak fitted in every frame, the distance where they agree) and
  fills it in when reliable; the label's tooltip gives the frames, χ²/dof and
  drift, or why it was not used — `pinhole.calibrate_distance` — addendum 3d.
- Pinhole geometry is the default (D40); "2θ range across levels"
  common/all.
- Scriptable: `exp.gid(...)`; Save GID writes the call to the Script pane
  (`docs/SCRIPTING.md`, "GID maps"). Save GID needs a map and Angles or Q
  axes (with Pixels it says so; it used to crash).

- Technical addendum: every GID patching option with advantages and
  disadvantages, terms and diagrams — `docs/manual/gid_patching.md`
  (figures `docs/manual/figures/gid_patching/`, by
  `tests/tools/gid_patching_diagrams.py`).

- GID Patch on frames that are not a GID set (one frame per Qz, as in a
  reflectivity scan) stops with a message naming the Qz level that has
  nothing to patch (2026-11-24); it raised a numpy error before.

### Figures of the pinhole geometry
- Eight figures of the exact pinhole trigonometry (lab frame, the
  direct-beam row and column, the pinhole from above, β depending on the
  column, the raised arm, the 200K's second module, and the footprint at the
  usual GID α with what makes a column usable: the S5 slit and the footprint): `docs/figures/pinhole/`
  (README there, written for non-specialists), made by `tests/tools/pinhole_figures.py` from
  `lss_core.pinhole` (Mati Meron's IMG_COO_CONV transform). Explanations
  are labels on the figures; each shows the footprint's reach against
  what S5 lets through.
- Case 8, what the finite S4 opening (S4L + S4R, 0.2 mm on NX) does: each
  column accepts 2θ over 0.079° (2.2 columns, the true resolution of the
  pinhole map), the footprint window's edges are ramps of ±1.2 columns,
  S5's edges barely move (±0.08), and counts per column grow in
  proportion to the opening (`pinhole.column_acceptance`, `s4_window`).

### Scan series (Stage 3, not in the window yet)
- "Scan i of N" lines and how cancelled runs are shown: proposal
  `docs/handoff_out/05-scan-series-syntax.md`; code `lss_core/series.py`.

### Live updates (2026-11-22)

- **Live** (beside Update Specfile): while ticked, the SPEC file, the
  Pilatus folder and the latest fluorescence scan's MCA file are checked
  every 5 s (preference `live_interval_s`); a new SPEC line, a new image
  or a new spectrum each triggers an update. What counts is the data on
  disk: a frame whose image has not arrived yet waits, and is added (to
  the frame selection, the plots and the remade results) when it does.
- Saved results whose series gained scans, or whose scans gained points,
  are **remade** from their recipe and saved as a new version (origin
  'live', note "remade from R…: why"); the old version is marked
  "superseded by R…". The Messages pane says which. Results without a
  recipe (SpecPlot curves, fitted MCA lines, GID cuts) are only marked out
  of date.
- A selection that was a whole series grows with the series; another
  selection is kept as it was. The tab, the SpecPlot axis choices and the
  frames selected in the image list are kept (all frames selected: the new
  frames join); nothing is redrawn when the new scans are elsewhere.
  "Update Specfile" works the same way (no reset).
- When the result being remade is the one on screen (the Reflectivity
  tab's curve, the MCA integrals, an open burn dialog, the GID map), the
  remade one replaces it there; it is not saved again. A GID map on screen
  stays on screen through an update until its remake replaces it.
- Remakes run in the background; the window stays usable. Frames left out
  of a result (its point selection) stay out of its remakes; frames and
  scans written since are added.
- Live mode stops by itself when the followed series writes that it is
  complete (needs the macro's series lines); otherwise untick it.
- Recipes are read, not run: only the reader's own reduction calls with
  plain values are accepted (`lss_core/live.py`).

### Automatic saving (2026-11-22)

- Every reduction carried through is saved into the workbook by itself:
  reflectivity patch, line cut and its fit, GID map and GID cut, MCA sum,
  line fit and merge, burn test. No note is asked; the Saved sheet's
  `origin` says 'auto'; a result identical to one already stored is not
  stored again (`content` digest), so redrawing does not pile up rows.
  The status bar says what was saved; the Messages pane stays quiet.
- The Save buttons still save a version with a note ('user').
- Preferences > Saving > "Save every reduction automatically" turns it off.
- SpecPlot curves are raw data, not a reduction: saved only by Save.
- GID maps are stored as grids in the Maps sheet (x across, a value and an
  error row per y): select the value block in Excel and add a colour scale
  to see the map.

### Saved results and their series (2026-11-22)

- Each Save records the series of its scans (id, kind, the series' data
  scans and status at that moment) and, when the reduction is scriptable,
  the lss_core call that remakes it (`recipe`; reflectivity patch, cuts,
  GID map, fluorescence sum, burn test). Columns in the Saved sheet.
- "Update Specfile": results whose series has since gained scans or
  changed status are marked out of date (`stale` column, a message in the
  Messages pane). Nothing is re-made automatically yet (live refresh,
  steps L1–L4 in TODO.md).

### Scan series in the scan list (2026-11-21)

- A **Series** list above the scan list: each series of the file (from
  its `#U Series` lines, or guessed: reflectivity, gid, xfntr, energy,
  burn) with "kind done/planned (status): S# scans"; its tooltip says why
  (missing or stopped scans, guessed or not, the macro). Choosing one
  selects its data scans as one action.
- **Whole series** (check box, on by default; owner): clicking a scan of a
  series selects all its data scans; Ctrl-click still removes one;
  alignment scans are selected alone; typed scan numbers are never
  widened. Off: one scan at a time, as before. Kept as a preference.
- Scan rows: a tooltip with the series, the position ("scan 2 of ?") and
  the status, and a faint tint by kind (blue reflectivity, green GID,
  orange XFNTR, purple energy, red burn, grey alignment).

### Burn tests (2026-11-21)

- The Burn test dialog opens on **Trends**, already analysed; the old plots
  are in the **Legacy** tab (the REF button and the GID list switch to it).
- Models (check boxes): constant, linear, exponential, double exponential,
  compared by AICc; "stable" when a constant fits as well as a line (the
  owner's good regime); the best model drawn thick, the others faint; a
  dotted vertical line at the confident 5 % time.
- GID: one panel per quantity (intensity, position, FWHM; owner,
  2026-11-21), each with a right-hand axis in percent: intensity and FWHM
  as % of the best model's value at t = 0, the position as its shift in %
  of the FWHM; grey dashed lines at ± the threshold. The summary (verdict,
  const − lin, best model, each model's Δ, the 5 % time, the limit, the
  settings) is beside the panels, not in the title. "Auto peak": the strongest peak of the mean frame; off: the
  typed Qxy range. Estimator: template (default), moments (legacy), fit.
  Errors: auto (scatter for GID, counting for reflectivity). Time: clock
  (default, wall time; the owner: the shutter closes between exposures) or
  exposure. Change: the threshold (5 %). "Position in limit": off by default
  (whether a position change matters is the user's judgment).
- Burn scans are recognised as `ascan ih` without movement (the beamline's
  standard), labelled 'burn' in the workbook's Scans sheet.
- Save stores the values and the trend table (Trends sheet).
- Figures: `docs/figures/burn_trends/` (`tests/tools/burn_figures.py`).
  Notes 2026-11-21.

### The Ref Patch window: Back, Cancel and the joins (F96, 2026-11-24)
- **<< Back** undoes the last step: the last Drop, or the last join
  accepted with Next. A join comes back as you left it, its drops kept.
  Press it again to go further back. Going back and repeating the same
  steps gives the same curve.
- **Cancel** (or Esc, or closing the window) stops the patch. The
  Reflectivity tab keeps the curve it showed, and the Messages pane says at
  which join the patch stopped. Closing the identical-scans window does the
  same. Starting a new Ref Patch while one is open replaces it, and says so.
- **The join table** under the buttons lists the accepted joins and the one
  on show (in italics): scans, factor ± error in per cent, where the factor
  came from (joint fit, legacy fit, or known ratio), the points dropped, and
  the fit's note. It stays with the result: it is in the tooltip of the line
  under the plot, and it is saved with the result in the workbook.

### Saturation cue on the frames (F97, 2026-11-24, Q-IMG-10)
- On the Pilatus tab, pixels counting faster than **1e5 counts per second**
  are drawn amber, and faster than **1.5e5** red: there an absorber is
  needed. A small red label in the frame's corner says how many pixels ("3 px > 1.5e5 cps:
  absorber needed"), and the tooltip over the frames explains the colours.
- Counts per second are the raw counts of the frame over its point's
  counting time (SPEC Seconds), not the per-monitor values the colour scale
  shows. In a sum of frames, a pixel above the limit in any frame is marked.
- The limits are the owner's figures for the Pilatus 100K. Whether the
  detector already corrected its counts for rate is not known here.

### Residuals above fits (F74, 2026-11-24)
- **View > Residuals above fits** adds a small panel above each plot that
  shows a fit: the SpecPlot scan fit and the cut peak fits, so far. It shows
  the residuals of the fitted points weighted by their errors,
  (y − fit)/σ, and the fit's legend label gains χ²/dof.
- For a good fit with the right errors the points scatter about zero,
  mostly within ±2. A pattern (a wave, a slope, a run on one side) means
  the model misses something; a spread much wider than ±2 means either the
  model or the errors are wrong.
- Off by default; the choice is kept between sessions. The plot's title
  moves above the panel while it is shown.
- Not yet on: MCA line fits, burn trends, the Ref Patch join preview, the
  older fit dialogs.

### Ref Patch checks: a message and marks (F95, 2026-11-24, Q-UI-B6, B3)
- Before joining, Ref Patch checks each frame: is the reflected beam more
  than 2 px from where the geometry puts it, and were bad pixels corrected
  inside the signal box? It used to stop for a box for each; now one
  message in the Messages pane names the frames (details in the log).
- Once the patch is on show, those points are marked on the Reflectivity
  plot: an open square for a beam off centre, a cross for bad pixels in
  the box. A point dropped from the curve has no mark.
- The **Bad Pixels** list at the top right of the Reflectivity tab gives
  the corrected pixels by Qz (scan, frame, pixels x, y). The correction
  itself is the Pilatus tab's (iterations, factor); the tab's own "Bad
  Pixel Correction fac" field is still unused (a separate ROI threshold is
  planned).

### The line under the Reflectivity plot (F96, 2026-11-24, Q-UI-B5)
- One short line says how the curve on show was made: patch method, error
  model, absorber model, scans, points dropped, and "saved vN" once it is in
  the workbook. Its tooltip lists the joins and the details.
- It describes the curve as it was made: changing a preference afterwards
  does not change the line (it changes the next Ref Patch).
- "saved vN" appears once the workbook has been opened in the session (by a
  Save, or by automatic saving).

### Greyed-out tools (2026-11-23, Q-UI-A10)
- On the Pilatus tab, Reflectivity and Ref Patch need a reflectivity series,
  GID Patch and the GID drop-down a GID series, and Burn Test a burn scan.
  When the selected scans are all of one known kind, the tools for other
  kinds are greyed out and their tooltip says what is needed. With no known
  kind, or a mixed selection, everything stays enabled.

### Reduction options (F86, 2026-11-23)
- **Preferences > Reduction options** (first on the page) chooses, for each
  action that has a legacy and a new path, which one it takes; nothing is
  removed (owner, 2026-11-23). **Reflectivity patch**: joint or legacy fit
  (moved here from the Ref Patch group). **Sum All**: counts and monitors
  summed then normalised (default) or the old average. **Ref Patch repeats**: summed by counts and monitors (default) or
  the old average. **GISAXS**: per Monc (default) or raw counts. **Fluorescence fit**: the MCA tab's one Fit action
  runs the line fit (default) or, when on, the legacy Fit dialog, and then
  also shows the legacy Fit, Fit All and Accept buttons. **Burn test**: shows
  the dialog's Legacy tab.
- **Ctrl+click** on Ref Patch or on Fit lines runs the other path once and
  writes a line in the Messages pane saying so; no dialog.

### State badges (F85, 2026-11-23)
- At the right of the status bar, three short labels show the settings that
  change numbers everywhere: the **error model** (legacy or budget errors),
  the **monitor normalisation** (/ Monc, / Monc / gain, / photon) and the
  **reflectivity patch method** (joint or legacy). A setting changed from
  its default is drawn amber. Hover for the detail; click to open the
  setting (the Errors pane, the SpecPlot tab, Preferences).
  **Preferences > Layout > State badges** shows them always, only when not

### The bottom panes (D59, 2026-11-23)

## Gaps a manual writer will hit

- No screenshots exist; the `run` skill or `tests/sweep.py` states can
  produce them on synthetic data (`sweep.state_*` functions set up typical
  states).
- Output-file column definitions are in code, not in one document.
- Several result panes are built only when data are loaded, so
  `controls.md` misses their controls; open NX school data and harvest
  again if needed.

- **Preferences → Ref Patch → patch factor** (2026-11-22): 'Joint fit' (default) or 'Legacy fit'. The joint fit draws one smooth curve through both scans at a join and fits the factor with it; its errors are honest and it has no interpolation bias (P1). 'Legacy fit' reproduces files made before 2026-11-22 exactly. The patch window's preview shows the factor that Next will use. Where a join has fewer than two points of a scan in the overlap the legacy fit is used and the Messages pane says so. Evidence: `docs/comparisons_data/ref_patch_gauntlet/summary.md`.

- **Preferences → Layout → "ngui (new layout, prototype)"** (2026-11-23, F82): off by default. Ticked, it opens a second window, "LSS Reader — ngui (prototype)", beside the main one: a sketch of the proposed layout (tabs Scans, Frames, Burn, Reflectivity, GID, Fluorescence, Files; the selection panel at full height; Messages, Script and Errors under the tabs). Nothing in it works: every control is a disabled placeholder whose tooltip says where it lives today and what it does; Help > Retired controls lists what the layout drops and why. Unticking closes it; the choice is kept between sessions. Design: `docs/gui/prototype.md`; screenshots: `docs/gui/prototype/screens/`.

## Tools menu and Tools window (2026-11-23, F84)

- **Tools** (menu bar, before Help): every demonstration and figure
  generator of the repository, by area; **All tools…** opens the Tools
  window at its overview. The list, the window and `docs/TOOLS.md` come
  from one catalogue (`lss_toolbox/catalog.py`), so the manual can take
  `docs/TOOLS.md` as it is: what each item demonstrates, its command line,
  its documented variations with their sources, the window's controls and
  their tooltips.
- A page: what the item demonstrates (the script's docstring in the
  tooltip), Docs buttons, a line saying whether the committed products are
  older than their code, **Settings** (Defaults or a documented variation),
  the script's own options, the **Command** it will run, **Run** (or **Open
  window** for the demonstrators, **Make and open** for a synthetic data
  set), **Stop**, **Replace the committed products** (only with the
  settings that made them). Results: **Show** (a run, or the committed
  products), **Compare with**, **Differences**, **Compare all** (images
  pixel for pixel: = same, ≠ different, + new), **Folder**.
- Runs go to `~/.lss_reader/tools/<item>/<date-time>` (or
  `$LSS_READER_TOOLS_DIR`) with `run.json` (command, times, exit code, git
  commit); the reader's logs and preferences of a run stay in that folder.
- A packaged build lists the items but cannot run them (no tools, no Python
  inside); the tooltip of Run says so.
- Manual idea: a page per menu with the figures it makes, taken from a run
  (the figure agent can use the same window, or `python -m lss_toolbox
  --audit`, to get current figures).
- File names (2026-11-24): SPEC names may contain dots (`run.v2`) and paths may use '/' or '\\'; plot-file legends show the file's name, the list '<folder>/<name>'.
- SPEC files (2026-11-24): when a scan's `#L` names more or fewer columns than its rows hold, the window says so once; the columns are still matched by position (a label with a space in it shifts the later ones).
- Motor names (2026-11-24): a scan's parameters hold each motor under its 8-character name (as the macro writes `#P`) and its full name from the file header's `#O` (`Two_Thet` and `Two_Theta`).
- SpecPlot (2026-11-24): an hklscan is plotted against the index it moves (from the `#S` command, else the column that varies; L when nothing moves); other scans against their first column; y the last column, as before.
- SPEC files (2026-11-24): L is Qz; a scan at fixed L whose L disagrees with its In_Rot and Out_Rot by more than 1 % is reported once on opening (a changed SPEC lattice would scale every Qz).
