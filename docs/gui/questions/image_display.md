# Questions for the owner: image display (`Q-IMG`)

These go with `docs/gui/image_display.md`. Each question says why it is
asked and what changes with the answer. Record answers beside each
question, dated.

| Id | Question | Why it is asked | What changes with the answer |
|---|---|---|---|
| Q-IMG-1 | Movie as the default **for every selection of more than one frame**, or only above a threshold (e.g. more than 6)? With 2–4 frames, would you rather see tiles? | F69 says movie by default and never more than 6 tiles. Small selections (a direct beam plus one frame, two repeats) may be easier to compare side by side | The rule in M5/M6: the switch from tiles to movie |
| Q-IMG-2 | Should the display mode and N be remembered **globally**, or **per scan kind** (e.g. movie for reflectivity, sampled 4 for GID, difference view for burn)? | "Sticky" can mean either. Per kind is more automatic but less predictable | The preference structure (P1) and what Reset does |
| Q-IMG-3 | Zoom: sticky **within a session only**, or **saved per SPEC file** (per kind) in the workbook so it is there when the file is reopened? | A saved zoom on the beam is handy across days; a stale zoom can hide data on a new sample | Whether the workbook Settings sheet gains display keys (P2) |
| Q-IMG-4 | In the movie, one **shared colour scale** for the whole selection (default proposed), or each frame scaled alone? For reflectivity scans with changing absorbers, should the shared scale use absorber-corrected values per monitor? | Shared limits let the eye compare frames (burn, repeats). Across absorber changes the raw counts jump by orders of magnitude | M4 default; whether the image is shown absorber-corrected by default (see Q-IMG-6) |
| Q-IMG-5 | Default scale by kind: **log** for reflectivity, GID and GISAXS frames, **linear** for direct-beam and dark frames, **asinh** for sparse low-count frames? Is a robust 99.9th-percentile top with the direct beam masked acceptable? | Today the scale is linear, from the first frame's maximum, which on NX reflectivity frames is the direct beam (100× the 99.9th percentile); every tile looks empty | The C4 table; the masks applied before limits |
| Q-IMG-6 | Units of the displayed image: **raw counts**, **per monitor**, or **per monitor, absorber-corrected** (proposed default, the same as the cuts and ROI numbers)? | Today frames show raw counts, but switch silently to per-monitor, background-subtracted values when a background is selected; cuts are per monitor. Users read numbers off the cursor | C5 default and colour-bar label; cursor readout shows both? |
| Q-IMG-7 | ROI close-up: a **side panel** (always visible, takes width) or an **inset** on the frame? And are the cue thresholds right: off-centre beyond 25 % of the half-width; clipped when more than 1 % of the integral lies on or beyond the box edge; background box within 2 px of the signal box? | The layout is decided once for both tabs. The thresholds decide how often warnings appear | R1 layout; R5 thresholds (recorded in OUTPUT_DECISIONS as display-only) |
| Q-IMG-8 | May raw frames be drawn with **nearest-pixel** rendering (no smoothing) by default? The GID map would keep optional smoothing | Today frames are bicubic-smoothed, which hides hot pixels and the shape of a beam a few pixels wide; the ROI close-up already uses nearest | C7; how the GID map looks by default |
| Q-IMG-9 | Do you need to **export a movie** (GIF/MP4) or frame sequences for talks or logbooks? | It is not in F69; easy to add later with the movie engine | Whether an export button and a dependency (imageio/ffmpeg) are planned |
| Q-IMG-10 | What count level should flag **saturation or "absorber needed"** on a Pilatus 100K/200K frame at ChemMatCARS (per pixel per exposure or count rate)? | The ROI close-up can warn when the peak pixel is too high; the right number depends on the counter mode and rate correction | R5 saturation cue; possibly a reflectivity quality flag |
| Q-IMG-11 | Are the **default cuts by kind** right? Reflectivity: V band through the specular column and H band through the reflected row, width = ROI slit. GID: Qxy integrated over the usable β range. GISAXS: H band at the Yoneda row. Burn: as the underlying kind | F68 says defaults may depend on the kind. Wrong defaults are worse than blind ones | X3 table |
| Q-IMG-12 | For the diffuse cuts of F59, which axes are needed first: **β**, **β − α**, **α_f**, **Qz**, **Qxy**? Should β − α be relative to the incident angle α (In_Rot) or to the specular angle from Qz? | Both α's exist in the code (`truealpha` from In_Rot, `alpha` from Qz) and differ on misaligned samples | X3 axis list and its definition (OUTPUT_DECISIONS row) |
| Q-IMG-13 | Burn scans: how should the reader tell a **reflectivity burn** from a **GID burn**? Proposed: Det_Th > 1° or Qxy ≠ 0 → GID, else reflectivity. Or will SPEC write `role=` / `kind=burn-gid`? | Display and cut defaults "as the underlying kind" need it; the series kind is just "burn" today | K1 rule |
| Q-IMG-14 | Is **jet** still wanted as an option (habit, legacy figures), with **viridis/magma** as defaults? | Perceptually uniform maps represent intensity faithfully; some users read jet faster from habit | C6 list and default |
| Q-IMG-15 | Should the GID map stay on the Pilatus canvas (replacing the frames), or get its **own view or tab**, so that frames and map can be seen without recomputing? | Today selecting any frame removes the map, and every map redraw takes about 3 s | Layout of phase 1b/2; whether GID products are cached per map |
| Q-IMG-16 | The second panel of today's ROI close-up ("w Corr", after the peak search) looks almost identical to the first on the NX data. Keep both, or one panel with the box moved to the found peak (old box dashed)? | It halves the space and makes the change visible | R1 layout |
