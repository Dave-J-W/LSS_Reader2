## Gotchas learned the hard way

- **Test a PR in a worktree** (`git worktree add --detach <scratch>/wtN origin/<branch>`, then
  `git merge origin/main`, then pytest there), and remove it afterwards. Never check out another branch in
  the main checkout.
- **Main moves while you test.** Re-fetch before merging, and if a PR shows "merge conflicts" (HTTP 405),
  merge main into your branch and push again. physics_notes conflicts are always two appended entries: keep
  both, in date order.
- **COMPARISONS numbers clash** when two sessions add a row at once. Take the next free number on main and
  re-point your references (C50 → C51 happened).
- **A `timeout` around a background sweep** must be longer than the sweep, with pytest's exit code recorded
  (`echo PYTEST_EXIT=$?`); a trailing `tail` hides it. The sweep is about 9 min alone and longer beside the
  quick suite.
- **The stop hook** asks to push unpushed commits and to commit uncommitted changes: do so (to my branch
  only).
- **Branches of other sessions can't be deleted from here** (proxy 403), and neither by git push. Ask their
  owner on #55.
- **`test_toolbox`** fails on a new script in `tests/tools/` without a catalogue item, and on a variation
  naming an option the script lacks. `docs/TOOLS.md` is re-rendered before a release or when asked, not per
  commit (rule 11, owner 2026-11-27; `pytest -m release` checks it).
- **`'%d' % nan` and `int(nan)`** both raise "cannot convert float NaN to integer": a message alone doesn't
  locate a crash.
- **Run the whole slow suite on main** (`pytest -m slow`, about 4 min) after a batch of merges by others, at
  least once a day. Sessions run the quick suite and the sweep, but rarely the slow one. A burn-dialog
  regression stayed red there unnoticed for hours (2026-11-25).
- **The owner's PC** fails 7–8 tests on clean main (paths, workers, ngui, toolbox GUI); its reports of "N
  failed" are environment failures. The cloud run is the check.
